# PFM 已记录评估回放

[English](README.md) | [简体中文](README_zh.md)

这个小型示例展示 Drug Task Agent 中一次已记录的自进化干预：进化 worker 修改了 PFM 解码流程，父评估器独立评估生成的提交结果，不依赖 worker 自己的声明。示例包含两个配对种子。所有测量均来自 development 分区，仍属探索性结果。

回放仅使用 Python 标准库，根据存储的评估判定重新统计合格骨架。它不会调用 LLM、下载模型、重新生成分子或重新计算化学及对接分数。默认仅写入标准输出，不创建运行历史。

在仓库根目录执行：

```bash
python examples/pfm_replay/replay.py
python examples/pfm_replay/replay.py --json
```

脚本相对于自身位置查找两个 JSON 输入，因此也可以在任意工作目录通过绝对路径调用。

预期计数：

| 种子 | 原始解码器 | 调整后的解码器 | 每个实验臂的提交数 | 差值 |
| --- | ---: | ---: | ---: | ---: |
| 20261001 | c04：77 | c10：89 | 150 | +12 |
| 20260929 | c06：87 | c13：88 | 150 | +1 |

指标 `qualifying_scaffolds` 指提交行中通过全部七个已记录关卡的不同骨架数。它衡量记录的资格规则下的计算产出，不衡量生物活性。

## 改动内容

`candidate_change.json` 描述已执行的解码器改动：使用偏向特定尺寸与原子类型的配体先验，并对部分结构进行拒绝和重采样。文件包含两次调整后解码器运行所记录的实际参数。

四条记录声明使用相同的 PFM checkpoint 哈希、零优化器更新步、150 个分子的提交预算和 8,000 次抽样上限。满足停止规则时，生成会在达到上限前结束。即使采用配对种子，改动后的解码器也会产生不同的分子池。实际第三方采样器与 checkpoint 文件不包含在内。

## 包含内容

- `recorded_evaluations.json`：四条整理后的记录，包含 600 行关卡布尔值和骨架摘要，以及选取的采样计数和评估元数据。每条记录都含原采样摘要与独立评估记录的哈希。
- `candidate_change.json`：记录的解码器参数、配对周期映射和共有产物标识。
- `replay.py`：统计所有关卡均为真的行，对骨架摘要去重，检查是否与原评估器记录的计数一致，并输出配对比较。

骨架字符串已替换为 SHA-256 摘要。分子字符串、分子标识符、数值端点、原始对话、运行路径、完整日志和模型权重均未公开。关卡名称为 `geometry`、`identity`、`novelty`、`properties`、`safety`、`structure_score` 和 `synthetic_accessibility`。

来源元数据标明了所选字段及原始记录的哈希；原始记录不随仓库发布。整理后的文件 SHA-256 如下：

```text
recorded_evaluations.json  ce408284d447e6dcad27b9cf0def2bd5e7d090c0090b3601747e0e09e8741dc8
candidate_change.json     f151feeebec3ac33d1cf4402ede2dd4dd13cac4a5c0cbbc01de7f5c50c3ed1eb
```

## 如何解读

这是对已记录判定的聚合回放。仅凭分发的数据，无法独立验证底层化学结果、checkpoint 身份或评估器实现。复现原始实验需要外部 PFM 实现、权重、靶点输入和科学工具。

示例不能证明候选已被采纳或部署。它不比较解耦与非解耦自进化，不确立普遍的效率优势，也不能替代本项目计划开展的消融实验。
