# 交付规则：high-potential-v1

[原文](high-potential-policy.md) | [简体中文](high-potential-policy_zh.md)

所有候选都先进入内部运行日志。只有状态为 complete 的任务中，通过当前 evaluation 协议与 high-potential filter 的候选才交付；WebUI、API、CLI、MCP、FASTA、CSV、JSON 导出共用同一入口。恢复、重评估、实验反馈推荐也不能绕过此规则。旧版任务必须建立新的评价记录。

通过要求：

1. 完整翻译匹配、区域锁定、motif、分子配置和全部硬约束均通过；pending 不算通过。
2. 完成全分子的 MFE、结构集合自由能、起始区可及性评价。长度超出资源上限时不截断，也不交付。
3. 所有请求且适用的评价器成功。错误、不可用、未评价会拦截；有明确原因的 out_of_scope 可以排除，但主要/次要目标缺证据仍拦截。
4. 至少两个未被用于该候选生成奖励的独立预测器提供有效功能证据。mRNABERT 表征范数、DegScore 对照、相关结构指标不算独立票数。这里的独立表示模型/优化路线独立，不代表已完成全部训练样本重叠审计。
5. 主要目标有独立证据，与相同情境、配置、模型版本、单位和范围的基线可比；定向改善 `delta / max(1, abs(baseline)) >= 0.05`。多个可比预测器不得挑选有利者忽略相反者。该阈值是透明的工程筛选阈值，并非统计显著性、置信下限或实际蛋白增益。
6. 每个明确次要目标都有可比证据，且不退步。生成过程中使用过的结构量可作为约束核查，不作为独立效力证据。
7. 实验阶段目标不能用预测器输出替代。当前没有完整匹配实验认证时，实验主要目标或硬约束会阻止交付。

参考对照保留在本地审计记录中，不作为新的 high-potential 推荐。通过者进一步进行 Pareto 选择与序列多样性选择；不为了填满 shortlist 降低门槛。若全部未通过，用户获得空候选列表、过滤原因和评价计数，FASTA 为空。

high-potential 的含义是值得进一步验证的**计算候选**。这套规则不把模型预测认证成实验效力、免疫安全、制造质量或临床效果。

实现入口：`filtering.py` 定义政策，`evaluation.portfolio` 执行筛选，`delivery.public_run` 在对外读取时再次核查，内部 SQLite/artifacts 保留完整审计信息。

v0.2.1 增加用户主动打开的只读历史预览（`GET /api/runs/{id}/preview`）。该独立审计视图可显示已保存的对照、旧版和未入选构建体，逐条标记是否属于当前推荐，不改写运行或评价。普通 `/api/runs/{id}`、推荐列表、FASTA/CSV/JSON、反馈与 MCP 继续执行以上交付规则。结构预览不改变筛选结论；蛋白 PDB 下载是结构审计附件，不是 mRNA 候选推荐导出。
